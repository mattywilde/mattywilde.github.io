Resonance Runner is a solo-developed prototype for a roguelike deck-builder built in Unity. The concept blends cyberpunk themes with “audio-hacking” mechanics, where the player battles hostile security programs using a deck of sound-based attacks. The core gameplay takes inspiration from Slay the Spire, featuring a unique “Compiler” system that lets players combine Core Signal (attack) cards with Codec (effect) cards to create synergistic abilities.

  • Persistent roguelike progression with a node-based map.
  • Full-featured deck builder and card collection menu.
  • Tactical turn-based combat with multi-enemy encounters.
  • Unique “Compiler” system for combining cards.
  • Data-driven enemy AI with telegraphed intents.
  • Advanced card effects (Splash, Volatile, Statuses).
  • Dynamic, reactive audio design via Wwise.

Game Architecture in Unity

The prototype is built around a modular, data-driven structure. ScriptableObjects store core data like encounter information, run progress, and balance parameters, keeping logic clean and easy to maintain. Prefabs handle interactive objects such as cards, enemies, and visual elements, allowing new content to be created or tweaked directly in the Unity Inspector without extra coding. Separating data from behaviour made iteration fast and the system easy to expand.

Managers like GameManager, RunManager, and AudioManager handle persistent data and player state across scenes, while BattleManager manages turn flow and combat logic. This modular setup simplified debugging and made it easy to add features like multi-enemy battles and branching map progression without breaking existing systems.

Audio Integration with Wwise

Because the game’s theme revolves around “audio hacking,” the sound system is central to its identity. Wwise manages all attack sounds through a single Switch container, where the selected attack determines which event plays. Each sound is then routed through a dedicated Effect Bus that contains all available effects. Each effect is linked to its own Game Parameter (RTPC), which controls whether it’s bypassed or active. When an attack triggers, the game activates the relevant RTPC so only the required effect runs, while all others remain bypassed.

Instead of using a fixed delay to disable effects—which would waste in-game time—the system uses a small queue feature. Each time an attack sound plays, the game stores the active RTPC name in memory. When the next effect triggers, it resets the previous one before activating the new parameter. This keeps the system efficient and ensures the correct effect is always active, even when sounds vary in length.

This dynamic audio setup helps make each attack feel responsive and distinct, reinforcing the “audio-hacking” concept at the heart of the game.

Ongoing Skill Development

Resonance Runner has been a major hands-on project for refining both my technical and creative skills. Through continued development and testing, I’ve been expanding my knowledge across multiple areas of game audio and implementation.

Technical Focus

  • Unity Development: Building modular systems and debugging complex interactions between managers and game states.
  • C# Programming: Writing efficient, maintainable gameplay and audio code, with an emphasis on modularity and readability.
  • Wwise Integration: Deepening understanding of real-time parameters, effect routing, and middleware performance.
  • Wwise Profiler: Using live profiling to monitor RTPCs, event calls, and system performance during gameplay.
  • Debugging & Optimisation: Iterating on system design based on profiler data to reduce unnecessary calls and improve responsiveness.

Creative & Design Skills

  • Sound Design: Creating and balancing layers of attack and UI feedback for clarity and impact.
  • Mixing & Implementation: Adjusting loudness, timing, and spatialisation to support gameplay readability.
  • UI & Graphic Design: Designing the interface and visual assets to fit the game’s cyberpunk theme.
  • Presentation: Recording and editing gameplay footage to document technical and creative processes.

Together, these areas have helped strengthen my understanding of how creative intent and technical systems work hand in hand to shape player experience.
